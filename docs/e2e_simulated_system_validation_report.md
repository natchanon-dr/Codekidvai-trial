## 5. Bug Found and Fixed During Validation

### Bug: `getPublishedTaskForScoring` blocked by RLS for students

**Root cause**: `mst_tasks` has only an admin/researcher RLS SELECT policy. The run-answer and submit-answer routes passed a student `userClient` to `getPublishedTaskForScoring`, which failed with "Published task not found" → 400.

**Impact**: Real students could not use run-answer or submit-answer in the current build.

**Fix applied**: `app/api/student/run-answer/route.ts` and `app/api/student/submit-answer/route.ts` — removed `userClient` from `getPublishedTaskForScoring` and `scoreTask` calls. These now use the admin client (service role) which can read published task data. Student-owned data (sessions, attempts, events, submissions) still uses the userClient for RLS enforcement.

**Recommendation**: Add a `student_select_published_tasks` RLS policy to `mst_tasks`:
```sql
CREATE POLICY "student_select_published_tasks" ON public.mst_tasks
FOR SELECT TO authenticated
USING (task_status = 'published' AND is_active = true);
```
This provides defense-in-depth even if the code fix is reverted.
